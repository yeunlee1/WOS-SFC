# 채팅 v2 — 웹 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 서브에이전트는 쓰지 않는다.

**Goal:** 웹이 서버 푸시 `chat:translation`과 히스토리 동봉 번역을 받아 즉시 표시하고, 빠진 번역만 배치로 요청하며, 감사 B·C에서 확정된 채팅 UI 결함(모바일 도크 z-index, spring 누락 규칙, 스크롤, 접근성, 중복 코드, 시스템 메시지 i18n)을 현재 테마 3종 안에서 고친다.

**Architecture:** 번역 동기화 로직을 `web/src/chat/translationSync.js`(순수 상태 기계)로 뽑고 `useSocket.js`는 이벤트를 연결만 한다. 번역은 메시지 객체가 아니라 별도 맵 `chatTranslations[id][lang]`에 둔다(도착 순서 무관). 메시지 항목 UI를 `ChatMessageItem.jsx` 하나로 합쳐 ChatTab·ChatDock·작전판 패널·동화 버전이 공유한다. 채팅 레이아웃 CSS는 테마 밖 베이스로 올리고 테마는 색만 덮는다.

**Tech Stack:** React 18, Zustand, Socket.IO client, Vitest + Testing Library, 순수 CSS(`web/style.css` 베이스 + `body.theme-*` 스코프, `web/src/story/story.css`).

**Spec:** `docs/superpowers/specs/2026-09-10-채팅-번역-v2-design.md`. 감사 근거: `클로드 출력물/2026-09-09-wos-오케스트레이션/보고서-B-채팅감사-웹.md`, `보고서-C-채팅감사-흐름계약.md`(항목 번호 B-n, C-n으로 인용).

### Task 4: 번역 동기화 상태 기계 `translationSync.js` (B Q1, C 5절 D·G·H·O)

**Files:**
- Create: `web/src/chat/translationSync.js`
- Test: `web/src/chat/__tests__/translationSync.spec.js`

**Interfaces:**
- Produces: `createTranslationSync({ store, translateBatch, emitLanguage, now = Date.now, setTimeout, clearTimeout })` → `{ onConnect(myLang, autoTranslate), onHistory(messages), onMessage(message), onPushed(payload), onLanguageChange(myLang), onAutoTranslateChange(on), onScrolledToOlder(ids), retry(id), dispose(), _debug() }`.
- 규칙. (1) `onConnect`·`onLanguageChange`·`onAutoTranslateChange`는 `emitLanguage(autoTranslate ? myLang : null)`을 호출하고 대기 타이머를 리셋한다. (2) `onPushed`는 `translations`를 즉시 병합, `failed`에 내 언어가 있으면 그 id를 15초 뒤 배치 후보에, `translations:{}`(대상 없음)이면 폴백 타이머를 취소한다. (3) `onMessage`는 자동번역 on이고 `unambiguousLang(text) !== myLang`이고 `text`에 글자가 있으면 15초 폴백 타이머를 건다. (4) `onHistory`는 내 언어 번역이 없는 항목 중 **최신 50건**만 후보에 넣고 1초 뒤 첫 배치. 나머지는 `onScrolledToOlder(ids)`로 들어올 때 20건씩. (5) 배치는 항목 ≤20 **그리고** 원문 합 ≤2000자, 요청 간 최소 1초, 동시 1개, 후보는 `markTranslationPending`. (6) 응답 `translated`는 병합, `skipped`는 조용히 완료, `failed`는 10초·30초 뒤 2회 재시도 후 `markTranslationFailed`. 429는 `retryAfterMs` 뒤. (7) `retry(id)`는 실패 표시를 지우고 즉시 후보에. (8) `dispose`는 타이머·진행 요청 취소. (9) 스토어에 없는 id는 후보에서 제외(C-3).
